## 意図分類ロジック（ArachneOrderIntentPlanner.java）

`order-service` の `order-intake-agent` は、自然言語メッセージを `DIRECT_ITEM` / `RECOMMENDATION` / `REORDER` / `REFINEMENT` の 4 種類に分類します。メッセージに商品名らしきキーワードが含まれているかどうかをヒューリスティックで先に判定し、その結果を LLM の structured output とあわせて正規化します。

```java
// ArachneOrderIntentPlanner.java
private static final List<String> DIRECT_ITEM_KEYWORDS = List.of(
    "セット", "box", "ボックス", "burger", "バーガー", "wrap", "ラップ", "soda", "ソーダ",
    "latte", "ラテ", "フライ", "fries", "チキン", "chicken", "サーモン", "salmon", "bowl", "dessert");

private boolean looksLikeDirectItemRequest(String message) {
    String normalized = message.toLowerCase(Locale.ROOT);
    // 「おすすめ」「向け」を含む場合は RECOMMENDATION に倒す
    if (normalized.contains("おすすめ") || normalized.contains("向け")) {
        return false;
    }
    return DIRECT_ITEM_KEYWORDS.stream().anyMatch(normalized::contains);
}
```

「テリヤキバーガーください」は "バーガー" にマッチして `DIRECT_ITEM` に、「子ども向けにいくつか」は "向け" を含むため `RECOMMENDATION` に分類されます。

## grounding context の受け渡し（MenuSuggestionPromptRequestFactory.java）

分類された `intentMode` と `directItemHint` は HTTP リクエストのペイロード（`MenuGroundingContext`）として `menu-service` の `POST /internal/menu/suggest` に渡されます。

```java
// MenuSuggestionPromptRequestFactory.java
static MenuSuggestionRequest build(String sessionId, SuggestOrderRequest request,
        NormalizedOrderIntent normalizedIntent) {
    // request.refinement() が空白なら null として渡す（menu-agent への追加制約）
    String refinement = request.refinement() == null || request.refinement().isBlank()
            ? null : request.refinement().trim();
    return new MenuSuggestionRequest(
            sessionId,
            normalizedIntent.menuQuery(),
            refinement,
            normalizedIntent.recentOrderSummary(),
            new MenuGroundingContext(
                    normalizedIntent.intentMode(),      // "DIRECT_ITEM" or "RECOMMENDATION"
                    normalizedIntent.directItemHint(),  // 商品名（DIRECT_ITEM の場合のみ）
                    normalizedIntent.partySize(),
                    normalizedIntent.budgetUpperBound(),
                    normalizedIntent.childCount(),
                    normalizedIntent.rationale()));
}
```

`order-service` が呼ぶ URL は `POST /internal/menu/suggest` のまま変わりません。grounding context は既存フィールドへの追記であり、エンドポイント自体のシグネチャは不変です。

## 明示指定と追加提案の型レベル分離（MenuApplicationService.java）

`menu-agent` は structured output で `explicitItemIds`（明示指定）と `additionalItemIds`（潜在ニーズ）を別フィールドで返します。コード側でそれを先頭固定にマージするため、AI の判断と型定義が整合しています。

```java
// MenuApplicationService.java
List<String> explicitIds = selection.explicitItemIds() != null
        ? selection.explicitItemIds() : List.of();
List<String> additionalIds = selection.additionalItemIds() != null
        ? selection.additionalItemIds() : List.of();

// explicit を先頭に、additional の重複を除外して結合する
List<String> mergedIds = Stream.concat(
        explicitIds.stream(),
        additionalIds.stream().filter(id -> !explicitIds.contains(id)))
        .toList();
```

## no-match を明示するシステムプロンプト（MenuApplicationService.java）

`menu-agent` の system prompt には、exact match が弱い場合でも「menu 側の代替として提案している」と summary に明示するよう指示が含まれています。

```text
exact match が弱い場合でも、menu 側で説明できる代替候補を同ブランド内から選んでください。
```

AI が「勝手に選んだ」とユーザーに見えないための設計上のコミットメントが、system prompt の文言として表現されています。

## 観察された振る舞い

- 「テリヤキバーガーください」→ `DIRECT_ITEM` → menu-service が alias-based explicit match で該当 ID を返した。
- 「子ども向けにいくつか」→ `RECOMMENDATION` → family-order-guide スキルが有効化され、Kids 系メニューと大人向けメインが提案された。
- menu-service が exact match できない場合、summary に「現行メニュー側の代替候補として提案しています」と明示された。
- どちらの経路でも `menu-service` は同じ `POST /internal/menu/suggest` を受け取り、API 契約は変わらなかった。
